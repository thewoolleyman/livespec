# Inventory: `livespec-dev-tooling/ci-runner/` excluding `k3s/phase2/`

Read-only classification of the committed tree at `master` HEAD of
`/data/projects/livespec-dev-tooling` (checkout clean), for livespec work-item
`livespec-sab5gn.4` Phase 0 "size the estate". `k3s/phase2/` is covered by
another agent; `k3s/phase2/install-node.sh` and
`k3s/phase2/reconstruct/converge-ci-stack.sh` were read only to learn which of
these artifacts they invoke or supersede.

Classes: (a) HOST GLUE, migrates to Ansible; (b) KUBERNETES-DECLARATIVE, stays
as manifests/values, Ansible only runs `kubectl apply` / `helm upgrade
--install`; (c) DEAD or ONE-SHOT; (d) REPO-SIDE, not host plumbing.

Hosts: `server` = poweredge-xubuntu (k3s server, cache-tier carrier),
`agent` = gmktec-xubuntu (k3s agent), `both`, `none`, or `other (named)`.

## Host-attribution findings that shape the table

- **The whole `gate-runner/` tier does NOT target poweredge-xubuntu or
  gmktec-xubuntu.** Its README, every unit header, and livespec
  `SPECIFICATION/non-functional-requirements.md` §"Fleet CI execution posture"
  place it on the **shared factory host** (the Fabro/Dolt/Dispatcher host,
  operator account `ubuntu`, `/data/projects/...` checkouts). Verified by file
  listing on this session's host `vmi3006760`: `/etc/systemd/system/gate-runner@.service`,
  `gate-runner-supervisor.service` (+ `.d/hosted-only.conf`),
  `gate-optin-expiry.{service,timer}`, `/etc/polkit-1/rules.d/50-gate-runner-supervisor.rules`
  and all six scripts under `/usr/local/lib/ci-runner/` are present, dated
  2026-08-23, matching the last `gate-runner/` commit (`65335aee`). The tier is
  LIVE (spec v214 permits exactly this one resident supervisor, opt-in gated,
  24h expiry); nothing in the tree invokes `provision-gate-runner.sh`, it is an
  operator-run converge. `ci-runner/README.md`'s opening sentence ("capacity on
  `poweredge-xubuntu`") is inaccurate for this tier.
- **`observability/` is server-only in practice.** `install-observability.sh`
  is not role-aware (installs all four timer pairs unconditionally), but the
  pool gauges and the webhook probe need cluster credentials only the server
  holds, the cache gauges read the cache-tier carrier's paths, and every
  Honeycomb trigger is filtered to `host.name = poweredge-xubuntu`.
  `phase2/install-node.sh` lists it as a node-local step it deliberately does
  not run. No units from this directory exist on the factory host (checked).
- **Phase-1 legs are superseded.** `install-arc.sh` / `install-kueue.sh` /
  `arc/values-host-unique.yaml` / `kueue/resources.yaml` remain listed as
  rebuild-sequence step 5 "phase-1 by-hand legs, superseded for boot durability
  by `phase2/reconstruct/`". `converge-ci-stack.sh` inlines their chart/manifest
  steps (never invokes them), applies `phase2/arc/values-poweredge-xubuntu-k3s.yaml`
  instead of `values-host-unique.yaml`, and applies
  `phase2/kueue/cluster-queue-phase1-proof.yaml` instead of `kueue/resources.yaml`.

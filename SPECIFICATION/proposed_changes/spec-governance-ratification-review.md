## Proposal: Make independent adversarial review an unconditional ratification floor

### Target specification files

- SPECIFICATION/spec.md
- SPECIFICATION/contracts.md
- SPECIFICATION/constraints.md
- SPECIFICATION/scenarios.md

### Summary

Lift the existing fleet instruction for independent adversarial review into the livespec contract, add `spec_governance.ratification_review` with manual-spawn and auto-spawn modes, and enforce the invariant that no accept or modify decision can ratify with zero review or with any blocker. The livespec fleet continues to designate Fable as its reviewer model without imposing that vendor-specific name on every livespec adopter.

### Motivation

The fleet already requires this review before every ratification in AGENTS.md and expands its checklist in .ai/spec-proposal-review.md; both are grounded by the maintainer's 2026-07-04 ruling. Repo thewoolleyman/livespec, plan/spec-side-autonomy/research/brainstorm.md classifies auto-spawn as Class (b): the reviewer is already AI and blockers already route to a human, so automating the spawn changes no doctrine. Contract ownership prevents the safety floor from depending on an agent remembering repository-local guidance. The in-tree rationale is simple: a mutating ratification needs non-zero independent verification just as any other irreversible governance transition does.

Scope note for the reviser, not text to ratify: this proposal preserves every Class (c) floor and does not edit repository livespec-orchestrator-beads-fabro, its `drive` action boundary, or any sibling proposed-change file.

### Proposed Changes

In spec.md under `## Intent preservation and design-record authority`, add the unconditional ratification floor: every proposed-change file MUST receive an independent, read-only adversarial review by a separately spawned reviewer agent with the project-designated adversarial-review capability, against the exact content to be ratified before any `accept` or `modify` decision is applied. The livespec fleet designation is Fable, grounded by the maintainer's 2026-07-04 declaration in repository thewoolleyman/livespec at `plan/spec-side-autonomy/research/brainstorm.md`; adopters designate an available model through the policy described below. The verdict MUST be `NO BLOCKERS`; any blocker, missing review, unavailable designated reviewer, stale review digest, or disagreement between review and decision MUST require maintainer input and MUST NOT be self-waived. Reject decisions do not ratify content and therefore MAY proceed without this precondition. The minimum review dimensions MUST be replacement-target fidelity, design-record fidelity, drift-sweep completeness, ratification mechanics, cross-repo consistency, claims that expire at ratification, negative assertions about sibling-owned surfaces, and clause lockstep. A `modify` decision MUST review the final modified proposal and resulting-file content, not only the originally filed text. Name this positive structural invariant `no ratification with zero independent review`.

Under the existing `## Sub-command lifecycle` heading, create or extend `### Spec-governance policy settings` and the core-owned top-level `.livespec.jsonc` `spec_governance` block. Add `ratification_review` (enum `manual-spawn | auto-spawn`, safe default `manual-spawn`, per-proposal override supported) and supporting `ratification_reviewer_model` (non-empty string matching `^[A-Za-z0-9._/-]+$`, safe default absent/unconfigured, no per-proposal override). A proposed-change MAY carry `ratification_review_policy: manual-spawn | auto-spawn`. `effective_ratification_review` MUST evaluate the unconditional floor and every blocker/unavailability condition FIRST, then the per-proposal override, global setting, and safe default. The setting controls only who initiates the required spawn: `manual-spawn` requires an attended session to dispatch it; `auto-spawn` requires revise operation prose to dispatch it automatically. A missing, malformed, or unavailable model designation requires maintainer input under either mode. Neither mode can remove the review or accept blockers. Evidence staleness is evaluated only when a decision is applied: stale evidence is invalid, but a fresh conforming review of the reassembled final bytes supersedes it without escalation. Missing/malformed mode config/front matter and unknown/wrong-typed values MUST resolve to `manual-spawn` and MUST NOT raise. Repository thewoolleyman/livespec MUST designate `fable` in its root `.livespec.jsonc` as an implementation co-edit when this contract is implemented.

Also amend spec.md `### revise operation-prose responsibilities` to add ratification-review dispatch and evidence assembly to its constitutive list. The prose MUST first assemble the final per-decision `resulting_files[]`; dispatch or consume the required review against those exact bytes; attach matching evidence; and only then invoke `bin/revise.py`. The existing statement that `bin/revise.py` MUST NOT invoke an LLM remains unchanged because the wrapper validates evidence but never spawns a reviewer.

Amend spec.md `## Proposed-change and revision file formats`, specifically `**Revision file format.**`. Re-derive its ordered enumeration so every `accept` or `modify` record includes a required `## Ratification Review` section immediately after `## Decision and Rationale`, carrying the evidence fields defined below; rejected records omit it. Preserve the conditional `## Modifications`, `## Resulting Changes`, and `## Rejection Notes` ordering after inserting the new section.

In contracts.md under `## Sub-command wire contracts`, create a `### Ratification-review evidence` subsection and extend revise input with per-accepted-or-modified-proposal evidence: reviewer model/identity, separate/read-only declaration, reviewed-at UTC-seconds timestamp, `NO BLOCKERS` verdict, proposal stem, and `content_digest`. Compute `content_digest` as the lowercase SHA-256 hex digest of `LP(P) || LP(path_1) || LP(content_1) || ... || LP(path_n) || LP(content_n)`, where `P` is the raw proposed-change file bytes; the `resulting_files[]` entries are ordered by ascending bytewise unsigned-byte comparison of the UTF-8 encoding of their exact schema `path` string, with no normalization applied because the schema's spec-target-relative path convention is canonical; each `path_i` and `content_i` is the UTF-8 encoding of the exact JSON string value; and `LP(x)` prefixes `x` with its byte length as an unsigned 64-bit big-endian integer. The wrapper MUST reject absent, blocking, malformed, or digest-mismatched evidence with the existing retryable validation exit 4 before any write. The required revision-record `## Ratification Review` section preserves all evidence fields durably.

Still under `## Sub-command wire contracts`, create or extend the core spec-governance control contract independently of sibling proposals. Its deterministic reference CLI is `.claude-plugin/scripts/bin/spec_governance.py`; it owns `--project-root <path> --show-effective`, allowlisted `--action <action>` policy edits, and validated `--journal-event-json <path>` appends. Create or extend the single declarative `ConfigKey` registry, the committed manifest `.claude-plugin/scripts/livespec/spec_governance/api_configurable_keys.json`, and the action grammar; amend any wrapper/CLI catalogue whose wording would otherwise exclude this non-LLM control CLI. Add `set-ratification-review:global:<manual-spawn-or-auto-spawn-or-clear>`, `set-ratification-review:proposal:<proposal-stem>:<manual-spawn-or-auto-spawn-or-clear>`, and `set-ratification-reviewer-model:<model-or-clear>`. The model setter validates its colon-free pattern; `clear` removes only the named value or override. The CLI MUST preserve unrelated JSONC keys/comments and Markdown body bytes through atomic replacement. A policy edit MUST NOT spawn a review, accept/reject a proposal, or mutate spec/history state.

Define one `awaits_ratification_review` predicate used by revise enforcement. It MUST remain true until matching no-blockers evidence exists; `auto-spawn` transfers ownership of satisfying it to the operation but does not report the gate retired before evidence arrives. Any awareness or advertisement surface that surfaces spec-side ratification review as awaiting human action MUST consume this exported predicate rather than re-derive it; core does not normatively name or own an orchestrator awareness surface.

Create or extend the append-only journal `<project-root>/tmp/livespec-spec-governance-journal.jsonl`, written through the reference CLI. Every automatic spawn and verdict MUST append an event naming `ratification_review`, effective source, proposal stem/content digest, reviewer identity/model, verdict, and escalation reason when applicable. Journal failure requires maintainer input and prevents ratification.

In constraints.md under `## Sub-command lifecycle mechanics`, state positively that safe defaults arm no automatic reviewer; the no-independent-review floor is unconditional under every mode; the reviewer must be separate, read-only, adversarial, and match the project designation; blockers are never self-waived; evidence uses the canonical content digest; and failure to spawn, journal, or validate evidence requires maintainer input before mutation. A design-record contradiction or missing/unreachable design record remains a mandatory review blocker. The floor governs spec-side ratification only; drift-origin proposals retain their separately ratified acceptance authority under spec.md `## Contract + reference implementations architecture`.

In scenarios.md, amend `## Happy-path revise` so its existing schema-conforming payload path explicitly assembles final payload bytes before review and includes matching evidence, then add manual-spawn and auto-spawn cases, a per-proposal manual override, and modified-content re-review. Extend `## Conflicting ratified statements resolve toward the cited design record` only with a cited-design-record contradiction producing a non-waivable blocker. Add `## Error path — ratification review blocks mutation` for a blocking verdict, unavailable or undesignated reviewer, stale/malformed digest at decision application, journal failure, and all-defaults behavior selecting manual spawn while retaining the floor. The revise payload MUST add that heading to `tests/heading-coverage.json` with a `TODO` reason explicitly acknowledging that integration-tier coverage remains required; if the then-ratified heading-coverage schema requires a `work_item`, the same payload MUST supply it. It MUST also maintain every new behavior clause's `clauses[]` link in the same `resulting_files[]` payload.

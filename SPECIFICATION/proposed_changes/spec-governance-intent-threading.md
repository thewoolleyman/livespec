## Proposal: Thread upstream authoring intent without redundant dialogue

### Target specification files

- SPECIFICATION/spec.md
- SPECIFICATION/contracts.md
- SPECIFICATION/constraints.md
- SPECIFICATION/scenarios.md

### Summary

Add safe-default spec-governance policy rows and explicit batch input envelopes for propose-change and critique so a supervising upstream caller or finding-disposition path can supply intent, topic, critique target, and alignment once without the operation prose asking for the same values again. Interactive behavior remains the default, and incomplete or conflicting batch input escalates without mutation.

### Motivation

The grounded design in repo thewoolleyman/livespec, plan/spec-side-autonomy/research/brainstorm.md, classifies propose-change intent/topic questions, critique-target questions, and routine in-flight alignment re-asks as mechanical gates with no doctrine behind them. Upstream callers already possess this context, but the operation prose cannot distinguish supplied context from missing context. This proposal adds a typed, auditable pass-through while preserving the interactive path and every human-only doctrine floor.

Scope note for the reviser, not text to ratify: this proposal does not edit repository livespec-orchestrator-beads-fabro or assign any spec-side action id to its `drive` executor. It also does not disposition any sibling proposed-change file.

### Proposed Changes

In spec.md under the existing `## Sub-command lifecycle` heading, create or extend a `### Spec-governance policy settings` subsection defining a core-owned top-level `.livespec.jsonc` block named `spec_governance`. The block MUST use independent keys, with no master autonomy switch. For this proposal add three declarative policy rows: `propose_change_mode` (enum `interactive | batch`, safe default `interactive`, no per-proposal override), `critique_mode` (enum `interactive | batch`, safe default `interactive`, no per-proposal override), and `in_flight_alignment` (enum `prompt | default-align`, safe default `prompt`, no per-proposal override). Missing config, a missing block/key, malformed JSONC, an unknown enum value, or a wrong-typed value MUST resolve to the safe default and MUST NOT raise. Each row MUST drive parsing, type-strict coercion, the committed API-configurable-key manifest, allowed-value diagnostics, and control-surface rendering from one declarative source.

Define hard-floor-first effective resolvers. `effective_propose_change_mode` and `effective_critique_mode` MUST resolve in this order: an internally contradictory upstream input envelope forces escalation first; then the envelope's optional `mode` field as the invocation-scoped override; then the global setting; then the safe default. Completeness is evaluated after that resolution: a mode that resolves to `batch` with a missing required field escalates. `effective_in_flight_alignment` MUST resolve genuine semantic conflict or any requested partial/full supersession to escalation before considering an explicit per-item `relationship` in the envelope, the global setting, or the safe default. `default-align` MAY satisfy alignment only when the new work is compatible with the surfaced in-flight item; it MUST NOT silently convert a conflict into alignment.

Define the LLM-layer envelopes without passing them to the Python mutation wrappers. A propose-change envelope MAY carry `mode: interactive | batch` and `spec_target`; when its effective mode is `batch`, it MUST carry non-empty `intent` and `topic` and MUST carry an explicit `relationship: align | modify-to-accommodate | supersede` for every surfaced in-flight item unless effective alignment is `default-align` and no conflict exists. A critique envelope MAY carry `mode: interactive | batch` and `spec_target`; when its effective mode is `batch`, it MUST carry non-empty `target`, using the same name as the operation prose's `Capture critique target` dialogue. When the effective mode is `batch` and its envelope is complete, core operation prose MUST consume those values and MUST NOT re-ask the corresponding intent, topic, target, or alignment question. When batch input is incomplete, ambiguous, or conflicts with a cited design record, the operation MUST escalate before invoking a mutating wrapper and MUST leave the spec tree unchanged. Interactive mode MUST preserve questions whose answers were not supplied.

Also amend spec.md `### propose-change operation-prose responsibilities`. Replace the unconditional alignment-intent requirement beginning `the alignment-intent capture: for each in-flight item surfaced above, the operation prose MUST elicit` with a conditional requirement: the prose MUST elicit a relationship only when a complete envelope has not already supplied it and `effective_in_flight_alignment` cannot safely resolve it. Amend the following `The narration MUST NOT gate the wrapper` paragraph so its sole-purpose sentence says the user or a complete compatible upstream envelope MAY choose alignment, modification, or supersession. These edits remove the otherwise contradictory unconditional MUST-elicit clause while preserving conflict escalation and the non-gating survey.

In contracts.md under `## Sub-command wire contracts`, define the envelope wire shapes above and create or extend the core spec-governance control contract. Its deterministic reference CLI is `.claude-plugin/scripts/bin/spec_governance.py`: `--project-root <path> --show-effective` returns the declarative manifest plus declared/effective values as JSON, while `--project-root <path> --action <action>` performs one allowlisted policy edit. The CLI is a config/control wrapper, not a ninth LLM-driven `/livespec:*` operation; amend any CLI-count or wrapper catalogue whose wording would otherwise exclude it. Create or extend a single declarative `ConfigKey` registry and the committed manifest at `.claude-plugin/scripts/livespec/spec_governance/api_configurable_keys.json`; when this proposal ratifies alone it creates the registry, manifest, CLI contract, and action grammar rather than presupposing a sibling proposal.

The global actions `set-propose-change-mode:interactive|batch|clear`, `set-critique-mode:interactive|batch|clear`, and `set-in-flight-alignment:prompt|default-align|clear` MUST accept only their declared values plus the reserved `clear` sentinel; `clear` removes the key so it re-inherits the safe default. A policy-edit action MUST modify only the named config value and MUST NOT invoke propose-change, critique, revise, doctor, a git state transition, or any orchestrator action. The reference CLI MUST use atomic config replacement and preserve unrelated JSONC keys and comments. The read surface MUST expose both the declared manifest and the effective values.

Create or extend the append-only JSONL policy journal at `<project-root>/tmp/livespec-spec-governance-journal.jsonl`, with the reference CLI as its sole core writer through a validated `--journal-event-json <path>` input. Operation prose passes only event fields, never an input envelope or raw intent, to that deterministic writer. Every batch-mode auto-consumption MUST append an event naming the operation, governing key, effective source, SHA-256 digest of the input envelope's UTF-8 JSON bytes, and outcome; raw intent text MUST NOT be duplicated into the event. A journal-write failure escalates and prevents mutation.

Define one shared predicate per operation, used by question enforcement: the predicate is true exactly when a human answer is still required after hard floors and effective policy resolution. Any awareness or advertisement surface that surfaces spec-side authoring input MUST consult this exported predicate rather than independently re-derive the condition. Execution remains Spec-Plane work performed by a supervising upstream caller or an attended Driver session; no spec-governance policy confers spec-side execution or store-write authority on an orchestrator executor.

In constraints.md under the existing non-interactive and sub-command lifecycle headings, state that batch mode changes only the operation-prose dialogue layer: Python mutation wrappers remain non-interactive, deterministic, and LLM-free, while the deterministic spec-governance control wrapper owns config edits and journal appends. Safe defaults MUST arm no unattended authoring; an invalid policy or incomplete envelope MUST fail toward human attention, never toward mutation. Audit records MUST be structured and MUST omit full user intent when a digest and proposal artifact provide sufficient traceability.

In scenarios.md, extend `## Happy-path propose-change` with scenarios in which a complete upstream propose-change envelope files a proposal without repeating intent/topic questions, a complete critique envelope runs without repeating the target question, and `default-align` consumes a compatible in-flight item. Add `## Error path — authoring batch input requires attention` for conflicting/incomplete envelopes, invalid settings, journal failure, and all-defaults behavior preserving interactive dialogue without writing. The revise payload MUST add that heading to `tests/heading-coverage.json` with a `TODO` reason and maintain every new behavior clause's `clauses[]` link in the same `resulting_files[]` payload.
